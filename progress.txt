## Codebase Patterns
- Project uses two Next.js route groups: `(frontend)` for public site, `(payload)` for admin/API
- PayloadCMS admin importMap is auto-generated via `pnpm generate:importmap` — do NOT edit `src/app/(payload)/admin/importMap.js` manually
- SQLite database stored at `data/payload.db` (gitignored)
- Tailwind CSS 4 uses `@import 'tailwindcss'` in CSS (no tailwind.config.js needed), configured via `postcss.config.mjs` with `@tailwindcss/postcss`
- PayloadCMS collections go in `src/collections/`, globals go in `src/globals/`
- Use `@/*` path alias for imports from `src/`
- Use `@payload-config` path alias for payload config import
- Seed script uses `tsx` to run TypeScript directly with path alias support (`pnpm seed`)
- `data/` directory must exist before SQLite can connect — seed or dev server creates the DB file
- PayloadCMS richText (Lexical) format: `{ root: { type: 'root', children: [{ type: 'paragraph', children: [{ type: 'text', text, version: 1 }], direction: 'ltr', format: '', indent: 0, version: 1 }], direction: 'ltr', format: '', indent: 0, version: 1 } }`
- Media uploads via Local API need `file: { data: Buffer, name, mimetype, size }` — use `fs.readFileSync`
- Make seed functions idempotent by checking for existing records before creating (query by unique field like `alt` or `title`)
- Programs schedule array entries have per-entry `registrationUrl` fields (each session links to its own LoveMyClub event)
- Registration URLs use full HTTPS URLs: `https://www.okmissiontennis.org/ClubMember/ClubEvent?ID={GUID}`
- Frontend components go in `src/app/(frontend)/components/` — client components use `'use client'` directive
- Layout fetches siteSettings server-side via `getPayload({ config })` + `payload.findGlobal()` and passes data as props to client components
- Use `lg:` breakpoint to toggle between mobile and desktop nav layouts
- App store badge images are in media collection (not linked to siteSettings) — query by alt text: `payload.find({ collection: 'media', where: { alt: { equals: '...' } } })`
- Server components (no 'use client') preferred when no interactive state needed — Footer is a server component, Header is a client component
- For interactive components (expand/collapse), use server page + client child component pattern — server fetches data, passes serializable props
- Use `RichText` component from `@payloadcms/richtext-lexical/react` to render Lexical rich text content
- Pages fetch data via `getPayload({ config })` as async server components — no need for API routes
